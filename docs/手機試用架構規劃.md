# 手機試用架構規劃（尚未啟用）

目前只完成本機 RWD 候選介面，沒有手機可直接點開的公開網址，也沒有開放區網服務或建立通道、憑證。

## 較符合「使用自己的 Codex」的方式

每個人各自在自己的 Mac 執行程式與自己的 Codex，手機作為同一位使用者的遠端操作介面。影片處理與 AI 指令仍由該人的 Mac 執行，Mac 必須保持開機。不要把朋友接到站主的 Codex 環境，也不要複製登入檔到共用主機。

這是依目前本機架構提出的設計方案，尚未實作或驗證遠端連線。手機本身不能直接執行 Codex CLI；只有手機、沒有自己的執行主機，仍無法使用現有程式完成全部流程。

## 可評估的私人連線

在確認已有合適的帳號與裝置後，可評估使用私人裝置網路及具身分驗證的 HTTPS 入口，將請求轉到 Mac 的 127.0.0.1。必須限定為自己授權的裝置與使用者；應用程式不能單靠知道網址就開放檔案操作。

Tailscale 官方文件區分 Serve（私人 tailnet 內）與 Funnel（公開網際網路）。Serve 也需要啟用 HTTPS 憑證並受存取規則管理；不是不需要授權的零設定捷徑。本次沒有使用任一功能。

- [Tailscale Serve 官方文件](https://tailscale.com/docs/features/tailscale-serve)
- [Tailscale Funnel 官方文件](https://tailscale.com/docs/features/tailscale-funnel)

## 啟用前需要明確授權的步驟

1. 確認要連接的 Mac、手機、使用者範圍，以及是否已有可用的私人網路帳號與客戶端；沒有帳號時不可擅自建立。
2. 補上私人入口的身分驗證與檔案／任務存取控制，驗證同源請求與代理標頭，不直接把現有後端改成對所有網路監聽。
3. 由使用者核准裝置加入、存取規則、私人服務入口及 HTTPS／憑證設定；目前指示禁止新增憑證，所以此步未做。
4. 在實體手機確認連線、觸控、軟鍵盤、短片匯入、儲存及匯出，驗證關閉連線與撤銷存取的方法。

如果日後要做多人共用的雲端網站，則要另行設計登入、每人檔案與執行環境隔離，以及適用的正式 AI 登入／計費整合。官方 Codex 文件明確限制既有 app-server 驗證用於託管服務，不能拿桌面登入檔解決多人雲端需求。

[OpenAI 官方 app-server 驗證說明](https://learn.chatgpt.com/docs/app-server#authentication)
